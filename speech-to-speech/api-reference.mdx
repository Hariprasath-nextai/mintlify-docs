## WebSocket Chat

Establish a WebSocket connection for real-time voice conversations with NextEVI's empathic voice interface.

### Endpoint

```
wss://api.nextevi.com/voice/websocket/{connection_id}
```

<ParamField path="connection_id" type="string" required>
  Unique connection identifier. Generate a UUID v4 for each new connection.
</ParamField>

### Method

**WebSocket**

Establishes a persistent WebSocket connection for bidirectional real-time communication.

### Authentication

NextEVI supports two authentication methods:

<Tabs>
  <Tab title="API Key (Query Parameter)">
    Pass your organization API key as a query parameter:
    
    ```
    wss://api.nextevi.com/voice/websocket/{connection_id}?api_key=oak_your_api_key&config_id=your_config_id
    ```
  </Tab>
  
  <Tab title="JWT Token (Header)">
    Pass JWT token via Authorization header (recommended for client applications):
    
    ```http
    Authorization: Bearer your_jwt_token
    ```
    
    ```
    wss://api.nextevi.com/voice/websocket/{connection_id}?config_id=your_config_id
    ```
  </Tab>
  
  <Tab title="JWT Token (Query Parameter)">
    Pass JWT token as query parameter (browser-compatible):
    
    ```
    wss://api.nextevi.com/voice/websocket/{connection_id}?authorization=Bearer%20your_jwt_token&config_id=your_config_id
    ```
  </Tab>
</Tabs>

### Query Parameters

<ParamField query="api_key" type="string">
  Organization API key starting with `oak_`. Required if not using JWT authentication.
</ParamField>

<ParamField query="config_id" type="string" required>
  Voice configuration identifier from your NextEVI dashboard. Defines the AI assistant's personality, voice, and behavior settings.
</ParamField>

<ParamField query="project_id" type="string">
  Project identifier. If not provided, will be auto-detected from the config_id.
</ParamField>

<ParamField query="authorization" type="string">
  JWT token formatted as "Bearer your_jwt_token". Alternative to Authorization header for browser compatibility.
</ParamField>

### Connection Flow

1. **WebSocket Handshake**: Client initiates WebSocket connection
2. **Authentication**: Server validates credentials and configuration
3. **Connection Metadata**: Server sends session information
4. **Audio Streaming**: Bidirectional audio and message exchange begins

### Send Messages

Messages you can send to the NextEVI server:

#### AudioInput

Send PCM audio data for real-time speech-to-text processing.

```json
{
  "type": "audio_input",
  "timestamp": 1645123456.789,
  "message_id": "audio-chunk-001",
  "data": {
    "audio": "base64-encoded-pcm-data",
    "chunk_id": 1,
    "sample_rate": 24000,
    "channels": 1,
    "encoding": "linear16"
  }
}
```

<ResponseField name="data.audio" type="string" required>
  Base64-encoded PCM audio data
</ResponseField>

<ResponseField name="data.chunk_id" type="number">
  Sequential chunk identifier for ordering (optional)
</ResponseField>

<ResponseField name="data.sample_rate" type="number" default="24000">
  Audio sample rate in Hz (8000, 16000, 24000, 48000)
</ResponseField>

<ResponseField name="data.channels" type="number" default="1">
  Number of audio channels (1 for mono, 2 for stereo)
</ResponseField>

<ResponseField name="data.encoding" type="string" default="linear16">
  Audio encoding format: "linear16", "mulaw", "alaw"
</ResponseField>

```json
    },
    "idle_timeout": {
      "enabled": true,
      "timeout_seconds": 300,
      "warning_seconds": 30
    }
  }
}
```

<ResponseField name="data.audio" type="object">
  Audio processing configuration
  
  <Expandable title="Audio Settings">
    <ResponseField name="sample_rate" type="number" default="24000">
      Audio sample rate (8000, 16000, 24000, 48000)
    </ResponseField>

    </ResponseField>
    <ResponseField name="encoding" type="string" default="linear16">

    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="data.turn_detection" type="object">
  Turn detection and conversation flow settings
  
  <Expandable title="Turn Detection Settings">
    <ResponseField name="enabled" type="boolean" default="true">
      Enable/disable turn detection
    </ResponseField>
    <ResponseField name="silence_threshold" type="number" default="0.5">
      Seconds of silence before ending user turn
    </ResponseField>
    <ResponseField name="min_speaking_time" type="number" default="0.3">
      Minimum speech duration to register as valid input
    </ResponseField>
    <ResponseField name="interrupt_threshold" type="number" default="0.8">

    </ResponseField>
  </Expandable>

<ResponseField name="data.emotion_detection" type="object">
  Emotion recognition configuration
  
  <Expandable title="Emotion Detection Settings">
    <ResponseField name="enabled" type="boolean" default="true">
      Enable/disable emotion detection
    </ResponseField>
    <ResponseField name="confidence_threshold" type="number" default="0.7">
      Minimum confidence score to trigger emotion updates (0-1)

  </Expandable>

      Seconds of inactivity before session timeout
    </ResponseField>
    <ResponseField name="warning_seconds" type="number" default="30">
      Seconds before timeout to send warning
    </ResponseField>
  </Expandable>
</ResponseField>

#### KeepAlive

Maintain connection during periods of inactivity.

```json

  "timestamp": 1645123456.789,
  "message_id": "keepalive-001"
}
```

### Receive Messages

Messages you will receive from the NextEVI server:

#### Transcription

Real-time speech-to-text results with emotion analysis.

```json
{
  "type": "transcription",
  "timestamp": 1645123456.789,
  "message_id": "transcript-001",
  "data": {
    "transcript": "Hello, how can I help you today?",
    "confidence": 0.95,
    "is_final": true,
    "start_time": 1645123456.500,
    "end_time": 1645123458.200,
    "words": [
      {
        "word": "Hello",
        "confidence": 0.98,
        "start_time": 1645123456.500,
        "end_time": 1645123456.800
      }
    ],
    "emotions": {
      "joy": 0.3,
      "neutral": 0.6,
      "surprise": 0.1
    }
  }
}
```

<ResponseField name="data.transcript" type="string">

#### Status

System status updates and lifecycle events.

```json
{
  "type": "status",
  "timestamp": 1645123456.789,
  "message_id": "status-001",
  "data": {
    "status": "session_started",
    "message": "Voice session initialized successfully",
    "details": {
      "features_enabled": ["emotions", "turn_detection"]
    }
  }
}
```

**Common Status Types:**
- `session_started` - Voice session successfully initialized
- `audio_started` - Audio processing began
- `turn_detected` - Speaking turn change detected
- `idle_warning` - Approaching session timeout
- `session_timeout` - Session ended due to inactivity

### Error Codes

<AccordionGroup>
  <Accordion title="Authentication Errors">
    - `AUTH_REQUIRED` - No authentication provided
    - `AUTH_INVALID` - Invalid API key or JWT token  
    - `SESSION_EXPIRED` - JWT token has expired
    - `CONFIG_NOT_FOUND` - Voice configuration not found
  </Accordion>
  
  <Accordion title="Audio Processing Errors">
    - `AUDIO_FORMAT_ERROR` - Invalid audio format or encoding
    - `TRANSCRIPTION_FAILED` - Speech-to-text processing failed
    - `TTS_FAILED` - Text-to-speech synthesis failed
    - `MICROPHONE_ERROR` - Client microphone access issues
  </Accordion>
  
  <Accordion title="Network Errors">
    - `NETWORK_ERROR` - Network connectivity issues
    - `RATE_LIMITED` - Request rate limit exceeded
    - `CONNECTION_TIMEOUT` - WebSocket connection timeout
  </Accordion>
</AccordionGroup>

```javascript JavaScript
      break;

  }
};
```

### Best Practices

<CardGroup cols={2}>
  <Card title="Connection Management" icon="plug">
    - Use exponential backoff for reconnection attempts
    - Implement heartbeat/keepalive messaging
    - Handle network interruptions gracefully
    - Close connections properly to free resources
  </Card>
  
  <Card title="Audio Streaming" icon="waveform">
    - Send audio chunks at regular intervals (100-200ms)
    - Use consistent sample rates throughout session
    - Implement audio buffer management
    - Handle microphone permission requests
  </Card>
  
  <Card title="Error Handling" icon="exclamation-triangle">
    - Implement retry logic with exponential backoff
    - Provide user feedback for recoverable errors
    - Log errors for debugging and monitoring
    - Handle rate limiting appropriately
  </Card>
  
  <Card title="Performance" icon="tachometer-alt">
    - Process messages asynchronously
    - Implement efficient audio encoding/decoding
    - Use connection pooling for multiple sessions
    - Monitor latency and connection quality
  </Card>
